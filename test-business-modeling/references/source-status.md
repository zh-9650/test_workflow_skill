# Source Status

业务理解阶段必须区分“证据直接支持”和“测试侧推导”。

## CONFIRMED
由当前正式证据直接支持。

要求：
- `source_refs` 非空；
- 不允许把模型常识、历史经验或旧项目规则放进这里。

## DERIVED
由当前已确认事实稳定推导。

要求：
- `derived_from` 非空；
- `source_refs` 可指向支撑推导的证据；
- 推导链必须可解释。

## TEST_BASELINE
人工允许为了继续测试暂按某口径推进，但尚非正式产品规则。

要求：
- 在人工文档中显式标注；
- 受影响 Scope 清楚；
- 正式规则变化后触发下游影响分析。

## PENDING
无法确定且不同答案会改变业务 Expected、流程、状态、关系或范围。

要求：
- 建立待确认/未知项；
- 标记 `affected_scopes`；
- 阻塞受影响范围。

## IMPLEMENTATION_DETAIL
不改变业务 Expected 的实现细节。

典型内容：
- 错误码；
- 事务实现；
- 日志存储；
- 异步技术机制；
- UI 具体文案。

它们可以继续保留为待确认/未知项，但不应伪装成业务规则。
