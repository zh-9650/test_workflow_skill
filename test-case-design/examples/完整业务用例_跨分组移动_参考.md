# 独立完整用例示例｜跨分组移动同名冲突

> **来源定位：** 采用此前已确认的知识库名称规则说明；不是已经从正式环境执行成功的结果，不代替该模块最新 PRD/权限核查。下面展示“每条用例描述清楚”的标准，不是系统接口或实际造数脚本。

## TC-KB-MOVE-001｜目标分组有同名知识库，跨组移动必须拒绝并保持原归属

**验证目标：** 证明目标分组名称唯一性校验和移动失败后的数据保持。**优先级：** P0（需结合项目风险最终确认）。

**数据准备要求（本用例独立完成）：**
- 同一租户 T，有两个不同分组 A、B。
- A 包含知识库 K1（真实 ID 记录为 id1），B 包含 K2（真实 ID 记录为 id2）；`id1 ≠ id2`，二者名称均为 `相同名称的知识库`。
- 测试账号具有跨分组移动 K1 的有效权限；确保不是由权限错误导致的拒绝。
- 使用已确认的合法分组/知识库创建入口建立数据（具体菜单/接口依项目当前原型/环境核实），不能假定 SQL 插入方式存在。
- **准备成功检查：** 在两个分组分别回读 K1/K2，记录它们真实 ID、名称、归属；确认 `K1∈A`、`K2∈B`、同名且不同 ID 后才执行。

| 步骤 | 具体动作 | 本步可判定预期 |
|---|---|---|
| 1 | 使用具移动权限的账号进入知识库管理，找到分组 A 的 K1，记录真实业务 ID 和当前所属分组 | K1 归属 A，名称与记录一致；该用户具有执行移动操作的资格 |
| 2 | 通过系统当前正式确认的跨分组移动入口，尝试将 K1 移入分组 B 并提交 | 依据目标分组名称唯一规则，本次移动应被拒绝；提示具体文案没有正式规则时不臆造 |
| 3 | 重新读取 K1、K2 的详情/列表并核对 id1/id2 与实际归属 | K1 仍属于 A，K2 仍属于 B；两个实体 ID、名称和关联没有因拒绝而发生部分变化 |

**独立判定依据：** 同一分组内知识库名唯一、移动时校验目标分组重名，以及被拒绝操作不得改变原有归属的业务一致性要求。**不能只看“移动失败”的 Toast**，必须核实真实归属没有错写。

**隔离清理与复测：** 记录生成的测试专用 id1/id2；依项目正式删除/恢复约束清理，避免影响其他用例。复测时本条用例独立重新准备 A/B/K1/K2，不要求其他用例先执行成功。
