# Parameterization

参数化的目标是复用执行骨架，不是合并结果。

一个参数化 Template 下，每组数据都必须有独立 `instance_id` 和独立结果槽。

允许参数化的必要条件：
- 相同主动作；
- 相同前置；
- 相同断言结构；
- 只差数据或条件组合。

不适合参数化：
- 不同业务流程；
- 不同恢复机制；
- 不同并发时序；
- 一个实例失败会改变后续实例环境且无法隔离。

## 1.2 正式输出规则（覆盖旧版对外“主项+执行数据组”的措辞）

**内部复用不能体现在外部省略。** 每一个独立数据组都必须展成完整 `case_id`：自带本组数据/数据准备入口/就绪核验/步骤/预期/Oracle/清理。生成 `full.md` 和 `standalone-cases.json` 时，绝不让人查另一个主项拼装。没有独立判别价值的值变化无需机械拆分。
