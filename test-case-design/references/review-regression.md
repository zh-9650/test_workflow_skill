# 版本继承与业务效果防退化清单

## 2026-10-09 实际 Skill 中必须保留

- Case Template + Execution Instance 双层模型；实例独立结果记录和参数化，断言绑定 TP；同一模板可覆盖多个 TP 但需要防失败遮蔽审查。
- 合法/非法数据、边界、判定组合、状态迁移、关系生命周期、失败原子性、恢复连续性、并发时序、旧状态、权限作用域、完整链中间断言。
- 7 列全量用例与 4 列冒烟用例、Grilling 待确认区、证据策略、呈现同步、Case Contract 2.0.0。

## 2026-10-21 已讨论但尚未实现的方案中采纳

- 先选场景再写模板、业务驱动+故障驱动双路径、数据/Oracle 的独立依据与准备完成判定。
- 场景实例粒度依据：不同业务结论/状态/注入位置拆例；纯数据复用模板但结果独立；被遮蔽机制分离验证。
- 步骤按业务状态与检查点拆；AI 不确定性质量不能生造唯一标准答案；下游数据准备、执行预演与真实环境就绪分离。

## 2026-10-22 最新上游强制适配

- 业务理解 3.3 最新有效子条款、来源效力、critical_paths、discriminators，不把历史 AI 断言或旧原型等同于当前需求。
- 测试点 1.1 所有分支、required_variations、discriminator_reviews、path_reviews 需形成可辨认 Case 实例与 Oracle；同一上游模型才能对比旧版/新版。不得以 TP 100% 覆盖假装分支 100%。

## 对人工评测的实际判据

来源跟踪命中与分支承接正确率；真实高风险场景漏失数；无意义重复实例数；数据“无辨别力/不能准备”占比；断言只看被测系统自报成功的占比；方法推导是否真的产生新有效场景；纸面预演需要多少补问；历史缺陷或固定错误挑战能否被对应断言检测。

对照应固定业务理解与测试点输入，隔离旧新版生成过程。另设来自上游 3.3+1.1 的新路径回归，不能在旧版没有分支输入的情况下直接说旧版生成结果不合格。代码测试全绿只能证明门禁逻辑在测试样例上有效，不足以证明真实用例总体优于历史版本。

## 2026-10-23 1.2 必须新增的回归义务

- 输出不再是模板/实例组合：`full.md` 每条 7 列记录含独立数据准备与预期；`case_cards.md` 每条完整卡片；`smoke.md` 每条完整；`standalone-cases.json` 每条完全展开。数量以独立可判定场景为准。
- `case_contract.py` 和 `design_contract.py` 与旧版哈希完全一致；沿用 1.1 的分支映射，不改业务预期。
- 反例必须拒绝：缺数据主体/对象/初始事实/决定性输入/准备方式/就绪核验/清理，缺步骤/断言/Oracle，跨用例 PASS 依赖，删掉冒烟完整前置，人工修改展示文件后不同步。
- 风险：因为试验所用旧合成样例本来要求先执行其它用例，1.2 会拒绝该样例作为正式独立交付。这属于**主动修正不合理旧能力**而非真实功能回归；仍须确保旧 Contract 对该旧样例本身保留兼容通过。
- 最终验收需要陌生测试人员只看随机抽取的一条用例“纸面独立执行”，和真实测试环境的造数/执行证据；75/75 工具测试不代表这一步已完成。
