# 项目知识读取与沉淀协议

项目知识可以来自Skill、人工、外部AI、开发说明、浏览器、脚本和报告。Skill是消费者与生产者之一，不能要求非Skill材料补造Run或阶段合同。

## 进入任务

1. 读项目的 项目记忆/开始这里.md，定位模块、需求版本、有效来源和实际环境。
2. 正式测试按 testing/测试线.yaml 选择当前聊天的测试线/Run，再读该Run的真实状态与next_action。不得以全项目最近目录代替任务选择。
3. 可通过项目 tools/project-memory/project_memory.py 的 context/discover/search 获取候选；工具输出不替代原文、业务确认或本次证据。
4. 优先使用已经绑定且适用的公共能力；找不到可靠能力时才调查真实接口链。对知识候选和历史经验保持原状态。

## 输出归属

- 规范规则进入模块/决策并保留来源与范围；代码事实、实测观察、历史线索分别标识。
- 当前计划、资源、执行结果与缺陷留在Run。仅把可转移的方法和结论作为共享候选。
- 公共能力有版本、证明范围、后置验证、失败/清理方式；使用失败时降级具体分支。
- 阶段结束结算候选，不要求用户阅读内部JSON。普通Run不自行发布通用Skill修改。
- 无Run材料用项目ingest登记；只有要转换成正式测试设计或执行结果时才应用相应阶段契约。

## 切换边界

若项目工作台声明迁移中，按测试线给出的唯一真实状态路径读取，不生成第二份状态。运行中的Worker和已确认产物需先核对安全边界。此协议不自动改阶段、确认、结果或安装版本。
